# 项目开发前必问清单

## 1. 项目定位和目的
- 这个项目的核心目标是什么？（解决什么问题）
- 用户的核心痛点是什么？
- 如果某个核心功能不可行，项目是否还有意义？

## 2. 部署平台
- 用户最终要在什么平台使用？（iOS / Android / Web / 微信 / 桌面等）
- 每个平台的能力限制是什么？（例如 iOS PWA 推送受限、Android 后台存活策略不同）
- 是否需要跨平台？优先级如何？

## 3. 技术约束
- 用户是否有自己的服务器？
- 预算范围？（纯免费 / 付费服务 / 自建）
- 是否接受第三方服务依赖？（如 Bark、Pushover 等）

## 4. 功能优先级
- 哪些功能是 MVP（最小可发布版本）必需的？
- 哪些可以后期迭代？

## 5. 本次开发教训（吃药闹钟项目）

**问题：** 项目核心需求是「苹果 iOS 准时推送提醒」，但前期未确认 iOS 平台限制就开始了纯前端 PWA 方案，导致：
- PWA 在 iOS 上后台 JS 会被冻结，无法准时推送
- Service Worker 的方案在 iOS 上不可靠
- 最终需要推倒重来，考虑 Bark / Pushover / Cloudflare Workers 等方案

**改进：** 以后新项目必须先问清上述清单，特别是「这个功能在目标平台上是否可行」。

## 6. 设计先行，代码后动

- 在写任何代码之前，必须先问用户：「你希望这个项目分为几个部分/页面？每个部分的功能和视觉设计是什么样的？」
- 在用户给出明确的页面分区和设计想法之前，不要开始写代码
- 每个部分确认后再推进，避免方向反复漂移
- 如果有类似 Figma 的设计工具可用，优先出设计稿再转代码
